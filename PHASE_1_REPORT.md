**This check found a real defect.** On the first attempt `npm run typecheck`
failed on the clean checkout with:

```
src/app/layout.tsx(31,50): error TS2304: Cannot find name 'LayoutProps'.
```

`LayoutProps<"/">` is a Next.js 16 type helper generated into `.next/types` by
`next typegen` (or by a build). A fresh clone has no `.next` directory, so the
type check failed before any build had run — while `npm run build`, which
generates the types itself, passed. The check had passed in the working
directory only because an earlier build had left `.next/types` behind.

**Fix:** the script is now `"typecheck": "next typegen && tsc --noEmit"`.
Re-verified on the clean clone with `.next` deleted first: exit 0, and the
whole suite (typecheck, lint, test, build) passes from a fresh checkout.

## 5. Architectural decisions

Full reasoning is in [docs/DECISIONS.md](docs/DECISIONS.md). The short list:

| # | Decision |
| --- | --- |
| D1 | Local-first; the only external service is the optional, user-supplied LLM provider |
| D2 | Separate Next.js and FastAPI applications, so provider keys never reach the browser |
| D3 | Environment-only configuration: `CLIPFORGE_*` (backend), `NEXT_PUBLIC_*` (frontend) |
| D4 | SQLite for job metadata, filesystem for media, under `CLIPFORGE_STORAGE_DIR` |
| D5 | Long-running media work goes to a background worker, never into an HTTP handler |
| D6 | A thin LLM provider abstraction; **no SDK committed to** until the provider is confirmed |
| D7 | The `/health` service name is a constant, not a setting, so the contract cannot drift |
| D8 | CORS lists explicit origins; a wildcard is rejected when settings load |
| D9 | Secrets are `SecretStr` — masked in logs and dumps, with a regression test |
| D10 | `/ready` publishes explicit capability flags so the API cannot over-promise |
| D11 | pytest + `TestClient` and Vitest + RTL; no browser-test framework added in Phase 1 |
| D12 | `turbopack.root` pinned to the frontend folder (see §1) |

## 7. Known limitations

1. **No video functionality exists.** No upload, no YouTube ingestion, no audio
   extraction, no transcription, no LLM analysis, no rendering, no captions, no
   export. The UI states this explicitly.
2. **No database and no filesystem layout yet.** `CLIPFORGE_STORAGE_DIR` is
   declared but nothing uses it.
3. **No authentication.** The API binds `127.0.0.1` and is a local tool only.
   Adding auth is out of scope for Phase 1.
4. **No end-to-end browser automation.** The integration check was manual and
   scripted in [docs/TESTING.md](docs/TESTING.md). Browser automation is
   scheduled for Phase 9.
5. **No Python type checker or linter.** The code is fully annotated and the
   API surface is validated by Pydantic at runtime, but `mypy`/`ruff` were not
   added, as no acceptance criterion required them.
6. **`npm audit` reports 5 high-severity advisories** in the dev-only ESLint
   plugin chain (`braces` ≤ 3.0.3 ← `micromatch` ← `fast-glob` ←
   `@next/eslint-plugin-next`). The advisory range is `<=3.0.3` and 3.0.3 is
   the newest release, so **no patched version exists**; npm's only offered
   "fix" is downgrading `eslint-config-next` to v14, which breaks the Next.js
   16 lint setup. The affected code only runs during linting and is not part
   of the shipped application. **Accepted, not remediated.**
7. **`NEXT_PUBLIC_*` is build-time.** Changing `NEXT_PUBLIC_API_BASE_URL`
   requires restarting the dev server or rebuilding.
8. **Node 26.4.0 was the runtime available.** Next.js 16 requires Node
   ≥ 20.9.0 and supports 22 LTS / 24 LTS; `package.json` declares
   `engines.node >= 20.9.0`. Everything was verified on Node 26.4.0; it was not
   re-verified on an LTS release.
9. **Rate limiting and request-size limits are not configured.** Not needed for
   a local tool, but they would be needed before the API is exposed beyond
   localhost.
10. **The `.openchamber/` screenshot folder** is left in the working tree for
    inspection; it is git-ignored.
11. **`npm run typecheck` depends on `next typegen`.** The generated route
    types are not committed (they live in the git-ignored `.next/`), so the
    script regenerates them first. A developer running bare `tsc --noEmit`
    instead of `npm run typecheck` on a clean checkout will see
    `Cannot find name 'LayoutProps'`.
